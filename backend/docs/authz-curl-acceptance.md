# 权限重构 curl 验收手册

本文档用于执行权限系统重构后的回归验收，确保 RBAC + 组织域隔离 + 审批流落地一致。

## 目标

确保以下能力全部可用且行为正确：

- 角色权限边界：`super_admin` / `admin` / `manager` / `volunteer`
- 组织层级隔离：上级可管下级、跨组织拒绝
- 审批流：`org` 作用域与 `global` 作用域审批规则
- 回滚防护：`rollback` 申请 scope 伪造拦截
- 通知系统：列表、未读数、单条已读、全部已读
- 公共资源访问：走失人员列表可匿名访问

## 前置条件

- 后端服务已启动：`http://127.0.0.1:8080`
- 本地数据库已完成权限重构相关迁移（含 `08`~`16`）
- 超级管理员可登录（示例：`13800138000` / `admin321456`）

## 一键执行

使用本地临时脚本（推荐）：

```bash
/tmp/authz_full_acceptance.sh
```

该脚本会自动：

- 生成测试组织树（A/A1/B）
- 生成多角色测试账号并激活
- 执行全链路权限验收
- 输出 `PASS/FAIL` 汇总

## 覆盖项（标准）

当脚本执行完成，需满足：

- `PASS` 全部通过
- `FAIL` 为 `0`

核心断言包括：

1. 志愿者不能访问管理接口（如 `/users`、`/system/authz/*`）
2. 经理可读用户列表但不可创建用户
3. 管理员不可直接改角色权限（super_admin 专属）
4. 上级组织管理员可在下级组织创建用户
5. 跨组织管理员创建/审批被拒绝
6. 管理员不能禁用超级管理员
7. `org` 申请不能自审，且必须在组织作用域内审批
8. `global` 申请仅超管可审批
9. `rollback` 的 scope 伪造会被拒绝
10. 权限通知接口全链路可用

## 已修复的关键兼容点

为保障 PostgreSQL 与 MySQL 一致性，已完成以下修复：

- UUID 列空值统一使用 `NULL`，不再写入空字符串
- 通知查询不再对 UUID 列使用 `COALESCE(uuid, '')`

涉及实现：

- `internal/infrastructure/repository/authz_repository.go`
- `internal/infrastructure/repository/system_notification_repository.go`

## 故障排查

若验收失败，请优先检查：

1. 迁移是否完整执行（尤其 `08`~`16`）
2. 当前登录账号角色与组织是否正确写入 JWT
3. 数据库是否存在历史脏数据（空字符串写入 UUID 列）
4. 是否使用最新后端二进制（重启服务后再验收）
